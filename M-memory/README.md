# M-memory: Your System's Memory

This is where the system learns. Every session adds to it. Every review improves it.

---

## The 4 Files

| File                  | What Goes In                                              | Who Writes                                            |
| --------------------- | --------------------------------------------------------- | ----------------------------------------------------- |
| `learning-log.md`     | What worked, what didn't, patterns discovered             | Gatekeeper after every review. You after any session. |
| `feedback-audience.md`| Audience reactions, comments, engagement signals          | You, after publishing content                         |
| `feedback-system.md`  | Your corrections and preferences when working with agents | Agents log it whenever you give them feedback         |
| `decisions.md`        | Strategic choices and why you made them                   | You or any agent when a decision is made              |

## The Loop

Memory is the engine of improvement. Here's how it works:

1. You create something (content, proposal, decision brief)
2. Gatekeeper reviews it and logs what it learned to `learning-log.md`
3. Over time, patterns emerge
4. Strong patterns get promoted to `C-core/voice-dna.md` or `C-core/project-brief.md`
5. Now every agent knows that pattern permanently

**That's The Loop.** Memory feeds Core. Core feeds agents. Agents create better output. Better output creates better memory.

## The Archive (Memory Decay Protocol)

> **Mandatory rule.** Every agent reads memory files at session start. Long files = expensive sessions. Decay keeps the system fast.

### The 90-Day Rule

Entries older than **90 days** move to `archive/[YYYY-MM].md`. Active files stay under ~500 lines.

### How Decay Works

1. **Monthly sweep:** at the start of each month, archive entries from 4+ months ago.
   - Example: on June 1, archive everything from before March 1 to `archive/2026-02.md`.

2. **Promote first, then archive.** Before moving an entry to archive, ask: "Did this pattern repeat 3+ times?" If yes, **promote it** to `C-core/voice-dna.md` so every agent knows it permanently. Then archive the original entry.

3. **Keep a marker.** At the top of the active file, note: "Entries before [DATE] are in `archive/[YYYY-MM].md`." This way future you (or future agents) can find old context if needed.

### Why This Matters

The system reads these files at the start of EVERY task. A 5,000-line learning-log costs significantly more per session than a 300-line one. Same outputs, less cost.

### What to Promote vs. Archive

| Pattern | What to Do |
|---------|-----------|
| Repeated 3+ times across departments | Promote to `C-core/voice-dna.md` |
| Repeated 3+ times in one department | Promote to that department's section in `voice-dna.md` or `company-glossary.md` |
| One-time observation | Archive after 90 days |
| Decision that no longer applies | Archive (don't delete) |

## Tips

- **Be specific.** "The hook worked" is useless. "Opening with a personal failure story got 3x more engagement than opening with a statistic" is gold.
- **Log immediately.** Don't wait. The insight fades fast.
- **Promote aggressively.** If the same pattern appears 3 times, it's a rule. Move it to C-core.
