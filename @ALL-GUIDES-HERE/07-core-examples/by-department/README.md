## How to Read These

Each file has the same structure:
1. The situation (what the person had to do)
2. The "before" version (what they'd write without the system)
3. The "after" version (what the system produced)
4. A diff table (what specifically changed and why)
5. The pipeline (how the system did it)

The point isn't that the "after" is longer or fancier. It's that it's specific, voice-matched, and catches things a generalist misses.

## What These Examples Are NOT

- Cherry-picked best cases. These are typical.
- Made up. The patterns shown are real patterns we see.
- Templates to copy. Each company's outputs will look different. The pattern is the lesson, not the words.
